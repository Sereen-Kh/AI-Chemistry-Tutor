تقرير بنية وتفاصيل نظام EduMind الكيميائي

1. الملخص التنفيذي

يغطي هذا التقرير التفاصيل الهيكلية والبرمجية لمشروع EduMind لتعليم الكيمياء لطلاب الصف التاسع، بالاعتماد على تقنيات الذكاء الاصطناعي التوليدي ومحركات الـ RAG.

جاهزية الخلفية (Backend)

ممتازة جداً. مبنية بـ FastAPI ونظام Celery للعمليات الخلفية الثقيلة مثل معالجة الـ PDF.

جاهزية واجهة الويب

متوسطة. الواجهة متفاعلة بـ Framer Motion ولكن تعتمد على بيانات محاكاة (Mock) في بعض المكونات كالـ Lab.

بنية RAG والذكاء الاصطناعي

متقدمة. تستخدم نماذج Gemini الحديثة مع معالجة ذكية للخطوات وإعادة الترتيب (Reranking).

تقييم مجالات النظام الأساسية

المجال حالة العمل الفجوة الرئيسية
الخلفية (Backend) مكتمل ومستقر تضخم ملف خدمات المحادثة الموحد.
واجهة الويب جزئي استخدام واسع لبيانات المحاكاة لخطوات الحل والواجبات المرفوعة.
قاعدة البيانات جاهزة حاجة لإضافة فهارس ربط إضافية في جداول السجلات RAG.

2. هيكلية المستودع

يحتوي المشروع على المجلدات الأساسية التالية:

src/
  backend/                              # تطبيق FastAPI ونظام Celery للمهام الخلفية
  frontend-web/                         # واجهة الويب React + Vite
  frontend/                             # تطبيق الهاتف Flutter
  docker-compose.yml                    # تنسيق تشغيل قواعد البيانات والخدمات محلياً

3. بنية النظام العامة

المخطط التالي يوضح آلية ربط المكونات المختلفة للخدمة:

graph TD
  Web[React Web] --> API[FastAPI Gateway]
  Mobile[Flutter Mobile] --> API
  API --> Auth[Security & JWT]
  API --> Chat[RAG Tutor Chat]
  API --> RAG[pgvector Semantic Search]
  API --> Solver[Guided Step Solver]
  RAG --> PostgreSQL[(PostgreSQL + pgvector)]
  RAG --> Redis[(Redis Cache)]
  RAG --> Gemini[Google Gemini API]

4. بنية الخلفية (Backend)

التطبيق مبني على مكتبة FastAPI القوية ويدعم العمليات غير المتزامنة بالتكامل مع SQLAlchemy AsyncSession.

  • نقطة الدخول الأساسية: src/backend/app/main.py
  • توزيع المسارات: src/backend/app/api/router.py
  • إدارة الجلسات: يتم استخدام get_db() للمسارات التزامنية و get_async_db() للمسارات غير التزامنية.

الواجهة مبنية بتقنيات React الحديثة مع إدارة مسارات محلية بـ React Router DOM.

7. بنية قاعدة البيانات

تنقسم قاعدة البيانات إلى عدة مجالات منطقية تخدم أهداف التعليم والتحليل التفاعلي للطلاب.

الهوية والتفضيلات

جداول users و student_profiles لحفظ الحسابات وتفضيلات ومستويات التعلّم.

منهج التعليم

جداول units، chapters، lessons، و topics لتقسيم المادة العلمية.

الـ RAG والـ OCR

جداول content_sources و rag_chunks لحفظ المقاطع المدروسة والمتجهات الكيميائية.

8. قائمة نماذج ORM الكاملة

يحتوي الكود على تعريفات الجداول التالية:

النموذج الجدول المفتاح الأساسي الحالة
User users id نشط
RagChunk rag_chunks id نشط (يدعم pgvector)
InteractiveSession interactive_sessions id نشط

9. علاقات الجداول

جميع نماذج ORM مصممة بآلية الحذف المتتالي (Cascade Delete) لتفادي وجود بيانات يتيمة في الجداول التابعة:

  • User يتصل مع StudentProfile بعلاقة One-to-One مع حذف متتالي.
  • ChatSession يتصل مع ChatMessage بعلاقة One-to-Many مع حذف متتالي.
  • ContentSource يتصل مع RagChunk بعلاقة One-to-Many مع حذف متتالي.

10. مخططات المعالجة

دورة حياة RAG

User Query --> Rewrite (Gemini) --> Embedding (embedding-001) --> Cosine Search (pgvector) --> Quality Gate --> LLM Response

12. بنية AI/RAG

يتميز نظام RAG بوجود بوابة جودة كاشفة (Quality Gate) تقوم بحساب جودة المسترجعات، وفي حال انخفاض معدل الثقة عن 0.70 يتم استخدام الشروحات المحلية المبنية على قواعد مسبقة التحديد (Litmus rules) بدلاً من توليد إجابات غير دقيقة.

13. بنية حل المسائل الموجه

المحرك التفاعلي يعمل كآلة حالة ذكية:

InteractiveSession (Active) --> Generate steps --> Student answers Step 1 --> Validate tolerance --> Go to Step 2
