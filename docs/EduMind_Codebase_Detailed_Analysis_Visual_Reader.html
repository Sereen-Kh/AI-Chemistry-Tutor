# Detailed Codebase Analysis: EduMind AI Chemistry Tutor

This document provides a comprehensive analysis of the EduMind Chemistry Tutor codebase, focusing on system architecture, database models, AI/ML models, APIs, RAG implementation, and the interactive Lab tab.

---

## 1. System Architecture Overview

EduMind is built as a split client-server web application designed to help Grade 9 students study Chemistry using Arabic-grounded AI tutors, interactive labs, and smart study planners.

*   **Backend Stack:** FastAPI (Python 3.10+) utilizing SQLAlchemy (async engine) with SQLite/PostgreSQL databases, Redis caching, and the Google GenAI SDK (Gemini).
*   **Frontend Stack:** React (TypeScript), Vite, React Router, TailwindCSS/Vanilla CSS, and a custom interactive design system built for RTL (Arabic) rendering.
*   **Media/Visuals:** Interactive HTML5 elements, Short Reels, and periodic table visualizers.

## 2. Database ORM Entities (SQLAlchemy Schema)

Below is the complete database model mapping:

### 1. User & Profiles (`app/models/user.py`)
*   `User`: Keeps student authentication credentials (`email`, `hashed_password`), current progress stats (`xp`, `level`, `streak_days`), and custom learning preferences:
    *   `teaching_style`: e.g. `real_life_examples`, `exam_focused`
    *   `answer_format`: `text`, `audio`, `image`, `video`, `reel`
    *   `teaching_level`: `simple`, `standard`, `academic`
    *   `explanation_method`: `direct`, `step_by_step`, `hints_first`, `exam_mode`, `real_life_example`
    *   `learning_modes`: list of active formats.
    *   `student_interests`: list of interests (e.g. `football`, `gaming`) to dynamically personalize prompts.
    *   `language`: `ar` / `en`
*   `UserInterest`: M:N linking of users to specific category interests.

### 2. Chemistry Curriculum (`app/models/chemistry.py`, `app/models/topic.py`)
*   `Unit`: Top-level groupings (e.g. Unit 4: Inorganic Chemistry) mapped to `semester` (1 or 2) and `unit_number`.
*   `Chapter`: Groups related lessons under a Unit (`unit_id`). Has `title_ar`, `order`, `difficulty`.
*   `Lesson`: Atomic studying unit. Has `chapter_id`, `title_ar`, `content_ar`, `order`, `difficulty`, `duration_min`.
*   `LessonProgress`: Tracks user completion state (`not_started`, `in_progress`, `completed`).
*   `Topic`: Specific conceptual tags (e.g., "التركيز المولي") linked to quizzes, flashcards, and weak-topic analytics.

### 3. Ingestion & RAG (`app/models/textbook.py`)
*   `ContentSource`: Raw file uploads/textbooks with metadata (`subject`, `grade`, `source_type`).
*   `RagChunk`: Vectorized pieces of textbooks/solution-books.
    *   `content`, `normalized_content`, `content_type` (e.g., `definition`, `formula`, `equation`)
    *   `embedding`: pgvector `Vector(768)` or `JSON` fallback
    *   `embedding_model`, `embedding_status`
    *   `unit_id`, `chapter_id`, `lesson_id`, `topic_id` foreign keys for metadata filtering.
*   `ExtractedQuestion`: Assessment questions mined during PDF ingestion.
*   `TextbookChunk`: Legacy textbook-only chunk table kept for backward compatibility.

### 4. Interactive Solving Lab (`app/models/interactive_solver.py`)
*   `InteractiveSession`: Represents one step-by-step problem-solving session (`problem_text`, `status`, `current_step_index`, `weak_topics`, `final_answer`).
*   `InteractiveStep`: A single action the student must take (formula selection, mL-to-L conversion, numeric substitution, final answer).
    *   `expected_answer_type`: `formula`, `numeric`, `final`
    *   `expected_formula`, `expected_numeric`, `expected_unit`, `tolerance`
    *   `hint_ar`, `explanation_ar`
*   `StudentStepAnswer`: Records student's input (`answer_text`, `is_correct`, `feedback_ar`, `parsed_value`, `parsed_unit`).
*   `MisconceptionEvent`: Captured errors for weak-topic tracking (e.g., "forgot_ml_to_l_conversion", "divided_in_wrong_direction").
*   `SkillMastery`: Aggregated mastery levels of a student across different chemical skills.

### 5. Quizzes & Spaced Repetition (`app/models/assessment.py`, `app/models/flashcard.py`)
*   `Question`: Multiple-choice questions.
*   `QuizAttempt`: User's quiz session results.
*   `QuestionAttempt`: Individual answer logs to extracted RAG questions.
*   `Flashcard`: Standard flashcard front/back.
*   `FlashcardProgress`: User SM-2 spaced repetition state (`ease_factor`, `interval_days`, `next_review_at`, `review_count`).

## 3. AI & Machine Learning Models

EduMind uses a hybrid AI architecture combining cloud-based LLMs with local or cloud embedding pipelines.

### LLM Integration (`app/services/ai_service.py`, `app/services/gemini_client.py`)
*   **Model:** `gemini-1.5-flash` (or customized model configured in settings).
*   **Purpose:** Chat-tutor generation, question simplification, quiz generation, step explanation, and semantic reranking.
*   **Fallback Handling:** Implements automatic exponential backoff, transient error retries (for 503/504 errors), and active failure cooldowns (e.g. temporarily disabling Gemini call on quota errors and falling back to local textbook RAG answers).

### Embeddings (`app/services/embeddings.py`)
1.  **Gemini Embeddings:** `gemini-embedding-001` (768 dimensions) using Google GenAI SDK.
2.  **Local Multilingual Embeddings:** Sentence-Transformers E5 model (`intfloat/multilingual-e5-base`), mapping inputs with specific prefixes (`query: ` / `passage: `).
3.  **Local Hash Embeddings:** A deterministic token-hash vectorizer used as a fallback for local smoke tests when keys are unavailable.

## 4. The RAG Pipeline Architecture

EduMind implements a state-of-the-art semantic RAG pipeline designed to retrieve context with high precision, especially for Arabic-language chemistry queries.

```
[Student Query] 
       │
       ▼
 1. INTENT ROUTER ────► Classifier (definition_lookup, exercise_solving, etc.)
       │
       ▼
 2. QUERY EXPANSION ──► Rewrite Query / Generate HyDE / Generate Multi-queries
       │
       ▼
 3. VECTOR SEARCH ────► Retrieve Candidates (Parallel Async Variants)
       │
       ▼
 4. FUSION ───────────► Reciprocal Rank Fusion (RRF)
       │
       ▼
 5. RERANKING ────────► Gemini Scoring + Content-type & Entity Boosting
       │
       ▼
 6. QUALITY GATE ─────► Score filtering against intent-specific thresholds
       │
       ▼
[Grounded Prompt] ────► Gemini Generates Personalized Response
```

### Steps of the Pipeline

1.  **Intent Classification (`app/services/chat_service.py`):**
    Classifies the incoming question into specific categories: `definition_lookup`, `property_lookup`, `formula_lookup`, `equation_lookup`, `reaction_query`, `table_lookup`, `book_grounded`, `exercise_lookup`, `exercise_solving`, `safety_question`, or `general`.
2.  **Query Expansion & HyDE (`app/services/semantic_rag.py`):**
    *   **Rewrite:** Rewrites student query for chemistry search terms in Arabic.
    *   **HyDE (Hypothetical Document Embeddings):** Generates a brief hypothetical book paragraph answering the query.
    *   **Multi-Query:** Formulates 3 alternative Arabic search terms.
3.  **Parallel Candidate Retrieval:**
    Invokes parallel database queries using cosine similarity over the `embeddings` column, filtering by `source_types` (`textbook` and `solution_book`), unit, chapter, lesson, or topic.
4.  **Reciprocal Rank Fusion (RRF):**
    Combines the results of the 5 parallel retrievals (original query, rewritten, hyde, multi-queries) using standard RRF logic: $Score = \sum \frac{1}{60 + Rank}$.
5.  **Hybrid Scored Reranking & Boosting:**
    The top candidates (up to 16) are sent to Gemini for a 0-10 relevance score. These scores are blended with:
    *   **Lexical overlap score** (Arabic-specific token matcher).
    *   **Content-type boosts:** Boosting `definition` chunks if intent is definition lookup, or `exercise` chunks for solving.
    *   **Chemical Entity matching:** Exact checks for compound formulas (e.g. $Na_2CO_3$, $HCl$).
    *   **Safety triggers:** Strongly boosting warning sections (such as "adding acid to water, not water to acid") when safety hazards are queried.
6.  **Quality Gate:**
    Filters out any chunks failing a minimum threshold (calibrated by intent, e.g., `0.52` for definition lookup, `0.48` for equations).

## 5. The Lab Tab & Interactive Solver

The **Lab Tab** (`/lab`) provides students with interactive tools instead of simply displaying answers. Its primary feature is the **Guided chemistry solver**.

```
[Input Word Problem] ────► API parses numerical values & solute formula
                                 │
                                 ▼
                     Create Interactive Session & Steps
                                 │
                                 ▼
                     Student submits Step 1 (Formula)
                                 │
                                 ├─► Correct? Advance to Step 2 (ML to L)
                                 └─► Incorrect? Misconception Event logged, hint displayed
                                 │
                                 ▼
                     Student finishes all steps
                                 │
                                 ▼
                    Generate Final Summary + citations
```

### How the Guided Solver Works

1.  **Problem Submission:**
    A student inputs a word problem (e.g., "محلول حمض كلور الماء HCl حجمه 100 mL ويحتوي 3.65 g. احسب التركيز الغرامي والمولي؟").
2.  **Numerical Parsing (`app/services/interactive_solver_service.py`):**
    The backend parses the problem text using regex to extract:
    *   Solute formula (e.g., `HCl`) and its molar mass (`36.5` g/mol).
    *   Given mass in grams (`3.65` g).
    *   Given volume in mL (`100` mL) or L.
3.  **Dynamic Step Generation:**
    Based on the parsed values, a deterministic solution plan is generated containing up to 7 steps:
    *   *Step 1:* Identify gram concentration formula (`Cg=m/V`).
    *   *Step 2:* Convert volume from mL to L (`0.1` L).
    *   *Step 3:* Calculate gram concentration (`36.5` g/L).
    *   *Step 4:* Calculate molar mass of solute (`36.5` g/mol).
    *   *Step 5:* Calculate moles of solute (`0.1` mol).
    *   *Step 6:* Calculate molar concentration (`1` mol/L).
    *   *Step 7:* Final answer check.
4.  **Step-by-Step Validation:**
    For each step, the student inputs their answer. The backend performs deterministic math validation:
    *   For formulas, it normalizes strings (stripping spaces, symbols, and checking aliases like `cg=m/v` or `التركيز=الكتلة/الحجم`).
    *   For numeric steps, it extracts values and units, validating with a strict $0.02$ tolerance limit.
5.  **Misconception Analysis:**
    If a student fails, specific misconceptions are flagged:
    *   *Forgot conversion:* student typed `100` instead of `0.1` on volume conversion.
    *   *Divided backwards:* student calculated $V/m$ instead of $m/V$.
    *   *Wrong molar mass:* incorrect atomic sum.
    *   *Missing unit:* correct number but missing `g/L` or `mol/L`.
    These are logged to the `misconception_events` table to update the student's **weak topics**.
6.  **RAG Citations:**
    The solver queries RAG for the problem's content and returns textbook page images and paragraph previews on the sidebar to help students verify rules.

## 6. Route and API Registry

Here is the list of active backend v1 route controllers:

*   **Authentication & Profile:**
    *   `POST /auth/register` - Create student account.
    *   `POST /auth/login` - Obtain JWT access tokens.
    *   `GET /auth/me` - Retrieve current profile and preference config.
    *   `POST /auth/onboarding` - Set interests and custom learning preferences.
*   **Curriculum Data:**
    *   `GET /units` - Get units filtered by semester.
    *   `GET /chapters` - Fetch chapters grouped by unit.
    *   `GET /lessons` - Fetch lesson titles and durations.
    *   `GET /elements` - Retrieve periodic table reference information.
*   **AI Chat & RAG:**
    *   `POST /chat/sessions` - Start a new chat tutor thread.
    *   `DELETE /chat/sessions/{id}` - Delete chat history.
    *   `POST /chat/sessions/{id}/messages` - Send message with custom tutor preferences.
    *   `POST /rag/retrieve` - Run search queries with vector score diagnostics.
*   **Interactive Solver:**
    *   `POST /interactive-solver/sessions` - Start a guided lab session.
    *   `GET /interactive-solver/sessions` - List active solving attempts.
    *   `POST /interactive-solver/sessions/{id}/answer` - Check step input.
    *   `POST /interactive-solver/sessions/{id}/hint` - Retrieve step hint.
*   **Study Plan & Progress:**
    *   `POST /study-plans` - Generate an AI-personalized calendar schedule.
    *   `GET /progress` - Fetch overall syllabus completion rates and weak topics.
    *   `POST /quizzes/generate` - Generate quizzes based on weak topics.
    *   `POST /flashcards/next` - Fetch flashcards due for SM-2 review.
