Database engine and runtime comparison

Local/dev

Docker Compose uses pgvector/pgvector:pg16. `.env.example` can default to SQLite for non-Docker dev, which triggers JSON embeddings and Python cosine scoring fallback.

Production

No explicit managed production provider was found in the repo. Backend Dockerfile exists, but production PostgreSQL/Redis/Gemini/ElevenLabs secrets are deployment gaps.

Redis

Used for Celery broker/result backend, semantic rewrite cache, RAG caches, and scheduled notification tasks.

Config risk

Tutor model default differs between code and `.env.example`; embedding dimension is fixed at 768 and requires migration if changed.

    • 4. Vector storage

  • Vectors are stored in PostgreSQL pgvector when settings.database_url starts with postgres and pgvector.sqlalchemy.Vector imports successfully; otherwise the embedding column falls back to JSON for SQLite/dev (src/backend/app/models/textbook.py:12-21).     • 5. Retrieval

  • Base retrieval is retrieve_context() (src/backend/app/services/rag.py:743-768). It cleans/rewrites queries, caches via Redis, embeds the query, filters RagChunk rows by source/unit/chapter/lesson/topic/page/content type, and logs retrieval (src/backend/app/services/rag.py:779-845, src/backend/app/services/rag.py:847-876, src/backend/app/services/rag.py:992-1016).
  • PostgreSQL path orders by RagChunk.embedding.cosine_distance(query_embedding) and fetches max(top_k*12, 48) candidates; SQLite fallback loads rows and scores in Python (src/backend/app/services/rag.py:880-910). Hybrid score blends vector and lexical scores with exact rules: vector/lexical blend uses 0.55 * vector + 0.45 * lexical when lexical matches exist (src/backend/app/services/rag.py:591-607), then intent/entity/source boosts are applied (src/backend/app/services/rag.py:618-722).
  • Semantic RAG wraps base retrieval with route_source, query rewrite, HyDE, multi-query, RRF, optional Gemini rerank, and quality gates (src/backend/app/services/semantic_rag.py:1-5, src/backend/app/services/semantic_rag.py:41-61, src/backend/app/services/semantic_rag.py:284-329, src/backend/app/services/semantic_rag.py:371-397, src/backend/app/services/semantic_rag.py:489-600, src/backend/app/services/semantic_rag.py:603-720). RRF uses _RRF_K = 60; rerank scoring uses either 0.68 retrieval + 0.24 lexical + RRF + adjustment or 0.46 Gemini + 0.34 retrieval + 0.14 lexical + RRF + adjustment (src/backend/app/services/semantic_rag.py:46, src/backend/app/services/semantic_rag.py:468-486).
  • Retrieval logs are persisted in rag_query_logs and retrieved_chunk_logs; logging writes query-level metadata and one row per retrieved chunk (src/backend/app/services/rag_logging.py:29-104, models at src/backend/app/models/rag_logging.py:12-78).
