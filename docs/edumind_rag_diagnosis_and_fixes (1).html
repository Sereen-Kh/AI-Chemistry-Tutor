Fixable issues found
1
min_similarity is 0.25 — you're accepting completely irrelevant chunks
Critical ▶
Your API spec shows min_similarity: 0.25. This means a chunk only needs 25% cosine similarity to be returned. At this threshold, almost every chunk in the textbook qualifies — the RAG is showing noise as results. The screenshots confirm this: scores of 28%, 30%, 31% are being returned and displayed to the student. These chunks have nearly zero relevance to the question.
Fix — raise threshold + add intent-based floor
# rag.py — change the thresholds # Before MIN_SIMILARITY = 0.25 # ← returns garbage # After: intent-based thresholds SIMILARITY_THRESHOLDS = { "definition": 0.58, # ما هو، ما هي → need close definition match "calculation": 0.52, # احسب، أوجد → worked examples are looser "exercise": 0.50, # تمرين → exercises can be broader "default": 0.55, # everything else } # Also add a HARD minimum — never show below 0.45 regardless of intent ABSOLUTE_MIN_SIMILARITY = 0.45
Expected improvement Scores jump from 28-44% to 55-80%. Irrelevant chunks stop appearing.
2
Hybrid scoring: 65% lexical weight is killing semantic matching
Critical ▶
Your architecture says: 0.35 * Vector Similarity + 0.65 * Lexical Score. This means keyword matching gets 65% of the weight. For short Arabic questions like "ما هي الاملاح؟", the lexical tokenizer often can't find exact matches in the chunks — Arabic morphology changes words heavily. So the lexical score is near 0, dragging the final score down to 35% of the real vector similarity. The REAL vector similarity might be 0.75 but after lexical dragging it becomes 0.26.
Fix — flip the weights
# rag.py — fix hybrid scoring weights # Before (killing semantic search) VECTOR_WEIGHT = 0.35 LEXICAL_WEIGHT = 0.65 # After (let the embedding model do its job) VECTOR_WEIGHT = 0.70 LEXICAL_WEIGHT = 0.30 # Reason: gemini-embedding-001 is trained specifically for Arabic # semantic similarity. Trust it. Lexical is a light correctness check, # not the primary signal. # The hybrid score function should be: def hybrid_score(vector_sim: float, lexical_sim: float, intent: str) -> float: v_weight = 0.80 if intent == "definition" else 0.70 l_weight = 1.0 - v_weight base = v_weight * vector_sim + l_weight * lexical_sim return min(base, 1.0)
Expected improvement Correct semantic matches will score 70-85%. "ما هي الاملاح؟" will find the salt definition page correctly.

The root cause — why all scores are 28-44%
Current (broken)
Vector weight: 0.35
Lexical weight: 0.65
Min similarity: 0.25

What happens: Gemini embedding finds the right chunk with 0.72 vector similarity. But the Arabic tokenizer fails to find "الأملاح" in the chunk that says "أملاح" (different form). Lexical score = 0.05. Final score = 0.35 × 0.72 + 0.65 × 0.05 = 0.28. That's why you're seeing 28%!
Fixed
Vector weight: 0.75
Lexical weight: 0.25
Min similarity: 0.55

What happens: Same chunk, same embedding. 0.75 × 0.72 + 0.25 × 0.05 = 0.55. Passes threshold. Returned to student. The LLM now has good content to answer from.
