1. Executive Summary

The frontend-web app is already a real React/Vite/TypeScript application with routing, a dark EduMind visual system, Arabic RTL setup, AI chat, lessons, study plan, notifications, quizzes, flashcards, and a Guided Lab MVP.

Current maturity:

  • Framework maturity: good. The app uses React, TypeScript, Vite, React Router, Axios, and Framer Motion.
  • AI tutor UX maturity: partial. The Ask AI page works, but it is still closer to a one-shot chat than a full learning workflow.
  • Guided Problem Solver maturity: promising. The feature exists under src/features/guided-lab, with mock fallback and a clean component split.
  • RAG transparency maturity: partial. Source cards exist, but source quality, answer scope, and AI fallback behavior need clearer student-facing design.
  • Backend alignment: partial. Many API calls align with /api/v1, but quiz, flashcard, study-plan generation, homework upload, and admin RAG endpoints are missing or mismatched.
  • Arabic/RTL readiness: good foundation. dir="rtl" and Arabic labels exist, but many Guided Lab and Lab labels are still English.
  • Accessibility: moderate. There are semantic components and focus styles, but some interactive cards, live regions, and icon buttons need cleanup.

Main blockers for a strong AI Tutor experience:

  1. The home dashboard is mostly static and does not use a backend aggregate endpoint.
  2. Ask AI silently falls back to mock answers on API failure, which can harm trust.
  3. Chat citations are displayed but not integrated into a persistent source panel or learning actions.
  4. The Lab needs stronger tool taxonomy and Arabic copy.
  5. Guided Lab is the best differentiator, but it needs full localization, resume/list states, and tighter backend response alignment.
  6. Homework solver UI is missing.
  7. Admin/RAG monitoring UI is missing despite backend admin RAG APIs existing.

8. Guided Problem Solver Design Recommendation

Guided Problem Solver should be positioned as a flagship feature, not a secondary tool.

Recommended MVP routes:

/guided-lab
/guided-lab/session/:sessionId

Keep final summary as a component inside the session page.

Required components already exist:

ProblemInputCard
ExampleProblemCards
SolverStepCard
StepProgressBar
SolverFeedbackCard
SourceCitationPanel
FormulaPad
FinalSummaryCard

Recommended flow:

  1. User opens The Lab.
  2. Clicks Guided Problem Solver.
  3. Enters or selects a problem.
  4. Starts guided session.
  5. Solves one step at a time.
  6. Gets correctness feedback.
  7. Requests hints only when needed.
  8. Completes final summary.
  9. Converts weak steps into quiz/flashcards.

Recommended UX additions:

  • Arabic-first labels.
  • Clear step status chips.
  • “Why was this wrong?” feedback mode.
  • “Show related source” button.
  • “Practice this weak step” CTA.
  • Session resume card on /guided-lab.

11. Arabic / RTL / Accessibility Findings

Arabic / RTL

Strengths:

  • Global lang="ar" and dir="rtl" are set.
  • Main app shell and many screens are Arabic-first.
  • Chat supports Arabic text.

Issues:

  • Guided Lab and Lab still contain English labels.
  • Chemistry formulas inside Arabic sentences need consistent bidi handling.

Recommendations:

  • Wrap formulas in <span dir="ltr">...</span> or a formula class.
  • Use unicode-bidi: isolate for formula snippets.
  • Test long Arabic questions in chat bubbles and solver cards.

Accessibility

Strengths:

  • Buttons and inputs are generally semantic.
  • Focus styles exist in CSS.
  • Loading and error states exist.

Issues:

  • Some card interactions should be buttons or links.
  • Some icon controls need clearer labels.
  • Notification live regions may be too noisy.

Recommendations:

  • Ensure all interactive cards are keyboard reachable.
  • Add aria-label to icon-only controls.
  • Use one aria-live region per page for updates.
  • Do not rely only on color for correct/incorrect state.

Responsive Behavior

Strengths:

  • App shell has desktop sidebar and mobile bottom navigation.
  • Guided Lab CSS has responsive sections.

Recommendations:

  • Manually test:
    • 360px mobile
    • tablet
    • desktop
    • long Arabic prompts
    • large source cards
    • solver sidebar stacked under main content

17. Final Recommendation

The frontend is beyond a prototype: it already has a strong shell, a coherent dark science theme, several real feature pages, and a promising Guided Problem Solver MVP.

The next step is not a visual redesign from scratch. The right move is to harden the learning experience:

  1. Make Ask AI trustworthy with clear source evidence and no silent mock fallback.
  2. Promote Guided Problem Solver as the flagship interactive feature.
  3. Add Homework Solver as the missing student workflow.
  4. Align quiz, flashcard, and study-plan API contracts with the backend.
  5. Add admin RAG monitoring screens for debugging retrieval quality.
  6. Improve Arabic localization, formula rendering, and accessibility.

If these are implemented in order, EduMind will feel less like a chatbot and more like a complete chemistry learning system:

Learn → Ask → Solve step by step → Get corrected → Practice weak topics → Review with flashcards → Prepare for exams
