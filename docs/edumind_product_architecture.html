Backend
Framework
FastAPI + Python 3.11+
Async-first. Native StreamingResponse for LLM token streaming. Auto-generates Swagger docs from type hints. Pydantic v2 for validation. Far better than Django for AI-heavy async workloads.
ORM + Migrations
SQLModel + Alembic
SQLModel = Pydantic + SQLAlchemy in one class. Works natively with FastAPI request/response models. Alembic handles schema migrations. Use async engine (asyncpg driver) for non-blocking DB calls.
Primary database
PostgreSQL 15 + pgvector
Single DB for relational data AND vector embeddings. pgvector extension supports cosine similarity search for RAG. Neon (managed, serverless) for production — has native pgvector support.
Cache + queues
Redis 7 + Celery
Redis: JWT refresh tokens, API response cache (5–60 min TTL), rate limiting. Celery: async tasks for TTS generation, image generation, reel creation — so API never blocks. Upstash Redis for production (serverless).

API conventions
Style: REST. Base URL: https://api.edumind.app/v1. Auth: Bearer JWT in Authorization header. All responses: {data: ..., meta: {request_id, timestamp}}. Errors: {error: {code, message, details}}. Pagination: ?page=1&limit=20 with meta.total, meta.has_next. Streaming: text/event-stream (SSE).

AI tutor architecture — 4 layers
🧠 Layer 1 — Prompt builder (personalization)
Every chat request builds a custom system prompt from the student's profile. This is the core of personalization — no fine-tuning needed, just smart prompt assembly.
# app/services/prompt.py def build_system_prompt(profile: StudentProfile) -> str: base = """You are a Grade 9 chemistry tutor. Only answer from the provided book context. If context doesn't cover the question, say so honestly. Always answer in {language}.""" style = STYLE_TEMPLATES[profile.teaching_style] # e.g. BEGINNER: "Use simple words. Define every term..." # e.g. REAL_LIFE: "Connect to student interests: {interests}..." format_inst = FORMAT_INSTRUCTIONS[profile.answer_format] # e.g. ["text","image"]: "End with: IMAGE: [description]" # e.g. ["voice"]: "Write in natural spoken language..." interests_ctx = build_interests_context(profile.interests) # Maps: football → "Use ball/team/pitch analogies" # cooking → "Use recipes/ingredients analogies" return f"{base}\n\n{style}\n\n{format_inst}\n\n{interests_ctx}"
📚 Layer 2 — RAG retrieval (accuracy)
All answers grounded in the official chemistry book. Filtered by lesson context for precision. Re-ranking ensures the most relevant chunks surface first.
# app/services/rag.py async def retrieve_context( query: str, lesson_id: str | None = None, top_k: int = 5 ) -> list[str]: # Embed the query query_embedding = await openai.embed(query) # pgvector similarity search # If lesson_id: filter to that lesson's chunks (scoped) # If None: search entire book (open-ended questions) chunks = await vector_store.similarity_search( embedding=query_embedding, filter={"lesson_id": lesson_id} if lesson_id else {}, k=top_k * 2 # over-retrieve ) # Re-rank by relevance score, return top_k return [c.page_content for c in chunks[:top_k]]
💬 Layer 3 — Conversation memory (context)
Short-term memory: last N messages per session (sliding window). Long-term: student weakness profile updated after quizzes. No fine-tuning — memory injected as structured context.
# Memory strategy per session SHORT_TERM_WINDOW = 10 # last 10 message pairs # Sent as messages[] array to Claude API # Long-term profile (updated after each quiz/feedback) LONG_TERM_CONTEXT = """ Student profile (injected into system prompt): - Weak topics: {weak_topics} → "focus more detail here" - Past confusions: {not_understood_count} on {topic} → "try a different analogy" - Preferred depth: inferred from feedback history """ # Session memory stored in: PostgreSQL (persistent) # Hot session cache: Redis (last 10 msgs, TTL 1hr) # Profile memory: student_profiles + student_weaknesses
🔁 Layer 4 — Feedback loop (improvement)
Every student interaction updates the personalization model. "Didn't understand" triggers a re-explain with a fresh analogy. Patterns accumulate into the student's long-term profile.
# Re-explain strategy when feedback = "not_understood" async def re_explain(session_id, message_id, profile): # Find which interest was used last time last_interest = get_last_used_interest(session_id) # Pick the next interest in the student's list next_interest = cycle_to_next( profile.interests, exclude=last_interest ) # Override the interests_ctx in the prompt new_prompt = build_system_prompt( profile, force_interest=next_interest, instruction="Student didn't understand. Try a completely different angle." ) # Stream new explanation to client return await stream_llm_response( system=new_prompt, messages=get_session_messages(session_id) ) # Long-term: after 3+ "not_understood" on same topic → # flag as weak in student_weaknesses table → # appears in dashboard recommendations

    state = state.copyWith(streamingText: state.streamingText + token);
